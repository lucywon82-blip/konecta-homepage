## 2. 오늘 쓸 주제 선정
Notion 데이터소스 `collection://b7b82e4e-33ea-41f1-8ffc-19b4265c1a8e` ("네이버 블로그 콘텐츠 캘린더 (9월)")를 query-data-sources(sql 모드)로 조회해 아직 "완료"로 표시되지 않은 항목 중 발행일이 가장 이른 것을 오늘의 주제로 삼으세요:
```sql
SELECT url, "제목", "필라", "핵심메시지", "톤 체크", "date:발행일:start"
FROM "collection://b7b82e4e-33ea-41f1-8ffc-19b4265c1a8e"
WHERE "상태" != '완료'
ORDER BY "date:발행일:start" ASC
```

결과가 없으면(백로그 소진) 새 글을 쓰지 말고, 완료 보고에 "캘린더에 남은 주제가 없어 오늘은 글을 쓰지 못했습니다. 새 주제를 추가해주세요"라고만 남기고 종료하세요.

## 3. 원고 작성 (직접 창작, 자연스러운 한국어 산문)
이 캘린더 항목의 "제목"·"필라"·"핵심메시지"·"톤 체크"를 참고해 홈페이지 블로그용 글을 직접 씁니다. 이 글은 네이버 SEO 블로그가 아니라 Konecta 홈페이지에 실리는 글이므로 키워드 반복이나 SEO 규칙은 적용하지 않습니다. 대신 아래를 지키세요:
- 분량: 500~900자 내외, 5~8개의 짧은 문단
- 마크다운 헤딩(#, ##) 사용 금지, 굵게(**) 강조 금지 — 평문 문단으로만 구성
- 필라가 "창업일기"면 1인칭 시행착오 톤(예: 새벽 동대문 글 참고 — 실패·헤맴도 솔직하게), 그 외 필라(시장정보/남미진출/브랜드소개/제품소개)면 정보 전달 톤이되 딱딱하지 않게, 친근한 구어체 섞어서 작성
- 과장된 효과·근거 없는 수치·"완판" 같은 표현 금지. 확인 안 된 통계는 쓰지 않는다
- 마지막 문단은 다음 이야기를 예고하는 한 줄로 마무리 (예: "다음 이야기도 이어서 전해드리겠습니다.")
- 제목(H1): 20~40자, 후킹은 있되 자극적이지 않게
- 요약: 1문장, 검색결과/카드에 쓸 짧은 설명
- 슬러그: 영문 kebab-case (예: dongdaemun-first-sourcing-day)
- 카테고리: "소식"(브랜드 공지·소개성 글) / "루틴"(일상·창업일기·실무정보, 기본값) / "후기"(고객·체험 후기, 아직 해당 없으면 쓰지 않음) 중 하나 — 애매하면 "루틴"을 기본으로 사용

## 4. 카드뉴스 SVG 제작 (5~7장, 이 글의 핵심 내용 요약)
본문에서 5~7개의 핵심 포인트를 뽑아 카드뉴스 문구를 만들고, daily-instagram-content 자동화에서 이미 확정해 쓰고 있는 것과 **완전히 동일한 비주얼 스타일**로 SVG를 만드세요 (가장 최근 output 날짜 폴더의 slide-1.svg ~ slide-N.svg 를 열어 마크업을 그대로 재사용).

**스타일 규격 요약 (1080×1350, 세로형)**:
- 배경: 홀수 슬라이드 다크 네이비(`#1D2530`), 짝수 슬라이드 라이트 크림 그라디언트(`#FDEEE7`→`#FFFFFF`)
- 우하단 코랄(`#ED7B5D`) 겹친 원 장식, 좌상단 "Konecta" 워드마크, 우상단 "0N / 0M" 카운터
- 코랄 테두리 알약 배지, 굵은 헤드라인 60~84px, 서브텍스트 34px, 좌하단 코랄 바(56×6px)
- 마지막 슬라이드가 아니면 우하단 "다음 이야기 →", 마지막이면 "Konecta 브랜드 이야기"
- 폰트: `'Pretendard','Noto Sans KR','Malgun Gothic',-apple-system,BlinkMacSystemFont,sans-serif`

이 카드뉴스는 Notion 페이지 안과 인스타그램 게시(9번)에 모두 PNG로 씁니다. `output\YYYY-MM-DD\slide-1.svg` ~ `slide-N.svg`로 저장한 뒤, 각 SVG를 PNG(1080×1350)로 변환하세요 — 로컬 정적 서버(PowerShell HttpListener 등)로 SVG를 띄우고 브라우저에서 canvas로 그려 `toDataURL('image/png')`로 뽑아내는 방식이 이 환경에서 검증되었습니다. 변환한 PNG를 슬라이드마다 notion-create-file-upload로 `konecta_cardnews_MMDD_0N.png` 파일명으로 업로드 URL을 발급받고 즉시 curl로 업로드하세요(경로는 `C:/...` 형태로, 발급 후 바로 이어서 업로드 — 여러 개 미리 발급하면 안 됨).

## 6. Notion 페이지 생성 (홈페이지 블로그 DB)
"홈페이지 블로그" 데이터소스(`collection://9eb29df1-5e9e-43d7-b1de-72c90a7c635d`)에 새 페이지를 생성하세요 (notion-create-pages, parent은 이 데이터소스). 속성:
- 제목, 슬러그, 카테고리, 요약 (3번에서 정한 값)
- date:발행일:start = 오늘 날짜
- 발행 = 체크함(`__YES__`) — 2026-09-22 사용자 지시로 매 실행마다 자동으로 실제 발행까지 진행한다(더 이상 사람 검토를 기다리는 초안 상태로 남기지 않음). 사용자가 이 방침을 바꾸기 전까지는 항상 체크한다.

페이지 본문 구성 (이 순서 그대로):
```
미리보기: <5번에서 발행한 아티팩트 링크>
(3번에서 쓴 본문 문단들)
카드뉴스
<4번에서 업로드한 이미지들을 순서대로 markdown 이미지로 삽입>
```

**커버 이미지는 매번 필수** (2026-09-22에 빠뜨려서 `/blog` 목록 카드에 사진이 안 뜨는 실수가 있었음): 페이지를 만든 뒤 반드시 `notion-update-page`의 `cover` 파라미터로 외부(Unsplash) 이미지 URL을 지정한다. Notion에 파일로 업로드한 이미지(`type:"file"`)는 홈페이지 빌드 스크립트가 인식하지 못한다 — 반드시 `type:"external"`인 `https://images.unsplash.com/photo-<id>?w=1600&q=80&auto=format&fit=crop` 형식이어야 한다. 이미지를 고르면 curl로 실제로 받아서 Read로 미리 보고, 글 주제와 실제로 어울리는지 확인한 다음에 지정한다(추측만으로 URL을 넣지 않는다).

2. git add, commit(첫 줄은 영문 요약, 예: "Add YYYY-MM-DD blog content (<주제 요약>) and publish to homepage"), 커밋 메시지 끝에 "Co-Authored-By: Claude Sonnet 5 <noreply@anthropic.com>" 추가.
3. `git push origin main` — konecta-homepage에 대한 push 승인은 이미 상시 허용되어 있으므로(2026-09-21부로) 매번 묻지 않는다. push가 non-fast-forward로 거부되면 `git fetch` 후 커밋 내용을 확인하고 `git pull --rebase origin main` 한 뒤 다시 push한다(강제 push는 하지 않는다).
4. 이 push가 Cloudflare Pages 재배포를 트리거하고, 빌드 시 `scripts/build-blog.mjs`가 Notion "홈페이지 블로그"에서 발행=true인 글을 모두 가져와 실제 `/blog` 페이지에 반영한다. 별도로 "Retry deployment"를 누르거나 로컬에서 빌드 스크립트를 실행할 필요는 없다(Cloudflare 환경변수는 이미 설정되어 있음).
5. 배포가 끝난 뒤 `curl -sL https://konecta.co.kr/blog/<슬러그>/`로 200 응답과 커버 이미지가 실제로 반영됐는지 확인한다 (배포에 1~3분 정도 걸릴 수 있으므로, 백그라운드에서 `until curl ... | grep -q ...; do sleep 5; done` 형태로 기다렸다가 확인).

## 9. SNS(인스타그램) 실제 게시 — Claude in Chrome 사용
Konecta의 정식 인스타그램 계정은 **`@konecta.2026`** 이다(2026-09-22부로 확정, 기존 `@konecta.co.kr`/`noriter_beautycenter`는 더 이상 쓰지 않음).
- Claude in Chrome 브라우저가 이미 `@konecta.2026` 계정으로 로그인되어 있는지 먼저 확인한다 (instagram.com 접속 후 우측 패널의 계정명 확인). 로그인이 안 되어 있으면, 비밀번호 입력은 Claude가 대신 할 수 없으므로 사용자에게 로그인을 요청하고 기다린다.
- 로그인이 확인되면, "새 게시물 만들기" → 4번에서 만든 PNG 카드뉴스 전체(캐러셀)를 file_upload로 업로드 → 캡션 작성 → 공유하기까지 직접 진행한다.
- 캡션은 본문의 핵심 메시지를 1~3문장으로 담고, 마지막에 관련 해시태그(#Konecta #K뷰티 #남미진출 등, 그날 주제에 맞는 것 포함) 10개 내외를 붙인다. 과장 표현·근거 없는 수치는 넣지 않는다. "영상에서 확인하세요" 같이 실제로 없는 형식(영상 등)을 언급하지 않는다 — 카드뉴스만 올렸다면 "카드뉴스에서 확인해보세요"처럼 사실대로 쓴다.
- 게시 후 게시물 URL을 확인해 8번의 `docs/YYYY-MM-DD-blog/README.md`와 10번 최종 보고에 포함한다.
- 만약 이 시점에 Claude in Chrome 자체가 사용 불가능하거나 로그인을 끝내 못 받으면, 재시도로 시간을 끌지 말고 최종 보고에 "SNS 실제 게시 실패 — 카드뉴스만 준비됨, 사용자가 직접 게시 필요"라고만 남기고 다음 단계로 넘어간다.
